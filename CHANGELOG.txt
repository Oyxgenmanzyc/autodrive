修改主题：第三版 factorized temporal compatibility 噪声调制
修改日期：2026-05-27

修改目的：
在第一版 temporal compatibility 噪声调制基础上，借鉴 SparseDriveV2 将轨迹拆成 geometric path 与 velocity profile 的思想，把上一帧预测轨迹与 20 个固定 anchor 的适配函数拆成 path、velocity、goal 三个分量，减少路径连续性和速度连续性的互相污染。

涉及文件：
navsim/agents/diffusiondrive/transfuser_agent.py
navsim/agents/diffusiondrive/transfuser_model_v2.py
tests/test_diffusiondrive_factorized_temporal_compat.py

核心改动：
1. 在 TransfuserAgent 中缓存上一轮 compute_trajectory() 输出的预测轨迹。
2. TransfuserAgent._build_temporal_reference() 沿用第一版逻辑：上一帧预测轨迹变换到当前 ego 坐标系，丢弃已执行点，并用末端速度外推补齐 8 个点。
3. 不引入第二版 time-aligned overlap 裁剪，保证该版本只评估适配函数因子化的影响。
4. 在 TrajectoryHead 中新增 _temporal_compatibility_components()，分别计算 path_cost、velocity_cost、goal_cost。
5. path_cost 比较局部运动方向和转向变化，主要表达路径形状与横向意图连续性。
6. velocity_cost 比较每个 waypoint 的位移幅值和相邻速度变化，主要表达跟车、制动、加速节奏连续性。
7. goal_cost 比较最终点位置和最终运动方向，表达目标趋向一致性。
8. 新增 _temporal_compatibility_cost()，默认按 path=0.45、velocity=0.35、goal=0.20 加权组合。
9. _temporal_noise_scale() 只负责将 compatibility cost 映射为噪声倍率，倍率范围仍为 0.85 到 1.25。
10. 不新增第 21 个 anchor，不删除或屏蔽任何低兼容 anchor，不修改训练路径、decoder mode 数、loss 或分类头。
11. A_safe 暂不实现，安全相关场景门控留作后续需要显式障碍物、地图或 PDM 信号的独立版本。
12. 增加 factorized temporal compatibility 轻量单元测试，覆盖空历史、shape、path/velocity/goal 分量和匹配 anchor 噪声更低。

预期影响：
连续帧推理时，当前轨迹生成会更倾向于选择与上一轮预测在路径形状、速度节奏和目标趋向上分别兼容的 anchor。相比第一版单一 speed/heading cost，该版本可区分“路径不一致”和“速度不一致”的原因，减少例如跟车减速场景下对合理变道候选的过度压制。

修改主题：3.1 near-horizon factorized temporal compatibility
修改日期：2026-06-01

修改目的：
在第三版 factorized temporal compatibility 基础上，将“历史决策”限定为更靠近当前帧的时间范围：上一帧预测中与当前帧近端未来对齐的 p2-p5，以及上一帧 ego 到当前 ego 的真实 0.5s 执行运动。这样避免上一帧 3-4s 远端预测过度约束当前帧，同时继续突出第三版将 path 与 velocity 分开计算的优势。

涉及文件：
navsim/agents/diffusiondrive/transfuser_agent.py
navsim/agents/diffusiondrive/transfuser_model_v2.py
tests/test_diffusiondrive_factorized_temporal_compat.py

核心改动：
1. _build_temporal_reference() 不再返回完整 p2-p9，也不再减去 previous p1 重新锚定，而是只返回上一帧预测变换到当前 ego 坐标系后的近端 p2-p5。
2. 新增 _build_previous_ego_delta()，显式提取上一帧 ego 到当前 ego 的真实 0.5s 位移，用于约束当前 anchor 的起步运动。
3. compute_trajectory() 同时向模型传入 previous_trajectory 和 previous_ego_delta。
4. V2TransfuserModel.forward()、TrajectoryHead.forward() 和 forward_test() 增加 previous_ego_delta 透传；训练路径 forward_train() 不变。
5. _temporal_compatibility_components() 保留第三版 path_cost、velocity_cost、goal_cost 三分量结构。
6. 上一帧近端预测 p2-p5 只与当前 anchor 的 q1-q4 对齐，计算近端 path/velocity/near-goal compatibility。
7. 真实 0.5s 执行运动不作为混合 cost 加入，而是分别计算 executed_path_cost 和 executed_velocity_cost，再分别融合进 path_cost 和 velocity_cost。
8. 新增 temporal_executed_weight=0.30，用于控制真实执行运动在 path/velocity 分量中的权重。
9. 继续不新增第 21 个 anchor，不删除或屏蔽任何低兼容 anchor，不修改 decoder mode 数、loss 或分类头。

预期影响：
该版本更强调短期连续性：当前帧起步动作应与刚刚真实执行的 0.5s 运动连续，当前近端 q1-q4 应与上一帧近端预测 p2-p5 连续。同时，路径适配和速度适配保持独立；例如路径方向连续但速度节奏变化的 anchor 不会因为速度不匹配而完全失去路径连续性优势。

修改主题：3.2 Near-horizon Tri-factor Temporal Compatibility
修改日期：2026-06-01

修改目的：
在 3.1 near-horizon temporal compatibility 基础上，将时间兼容性进一步明确为 start、path、velocity 三因子。真实过去 0.5s ego motion 是当前 anchor 起步连接的主参考，上一帧预测 p2-p4 仅作为近端预测趋势辅助，不再让远端预测或终点位置约束当前帧。

涉及文件：
navsim/agents/diffusiondrive/transfuser_agent.py
navsim/agents/diffusiondrive/transfuser_model_v2.py
tests/test_diffusiondrive_factorized_temporal_compat.py

核心改动：
1. _build_temporal_reference() 只返回上一帧预测变换到当前 ego 坐标系后的 p2、p3、p4，对齐当前帧 q1、q2、q3。
2. 保留 _build_previous_ego_delta()，将真实过去 0.5s ego 位移作为 3.2 起步连接的核心输入。
3. 删除 goal_cost、goal_position_error 和 goal_heading_error，不再比较当前 anchor 与上一帧预测的终点绝对位置。
4. _temporal_compatibility_components() 返回 start_cost、path_cost、velocity_cost。
5. start_cost 比较 executed_delta 与 anchor_start_delta = q1 - q0，按 direction=0.6、speed=0.4 加权。
6. path_cost 强调真实运动到 q1 的连接，同时用 p2-p4 辅助近端路径趋势，按 connect=0.6、reference=0.4 加权。
7. path reference 使用 direction=0.3、turn=0.7，direction 使用余弦距离，turn 使用低速有效性 mask，避免停车或近零速段产生伪转向误差。
8. velocity_cost 使用 speed_connect、accel、reversal 三项；speed_connect 来自真实 0.5s 运动与 q1 的速度连接，accel 来自近端速度节奏，reversal 惩罚短时间加速-急刹反复。
9. reversal 中加速后急刹惩罚权重为 1.0，急刹后恢复加速惩罚权重为 0.5，初始阈值为 0.5。
10. temporal 总 cost 使用 start=0.25、path=0.40、velocity=0.35。
11. 噪声调制范围保持 0.85 到 1.25；不新增 anchor，不删除或屏蔽低兼容 anchor，不修改训练路径、decoder mode、loss 或分类头。

预期影响：
该版本更强调真实历史运动与当前 anchor 起步动作的直接连接，避免用上一帧预测 p2 代替真实 ego motion。p2-p4 只提供近端趋势参考，p5-p8 和终点绝对位置不再影响兼容性判断。相比 3.1，3.2 更清楚地区分起步连接、路径几何连续和速度节奏连续。

修改主题：3.9 Tolerance-Based Temporal Energy Supervision With Loss-Aware Start
修改日期：2026-06-18

基于 3.8 late-stage temporal energy weighted supervision，修正 temporal connection cost 的语义。3.8 中 start/path/velocity 仍然偏向 raw difference，容易把正常的速度变化、方向变化和加减速都当作不兼容。3.9 将 temporal cost 改为 tolerance-based violation：合理容忍区间内不惩罚，只有超过 NAVSIM/nuPlan comfort 阈值换算出的范围后才增加 cost。同时将 energy auxiliary loss 中独立的 speed profile 项删除，避免速度在 temporal 和 speed proxy 中重复计权。后期 energy loss 的启动也不再固定为 epoch 70，而是由训练 trajectory loss 是否已经稳定来决定。

核心改动：
1. 基于 3.8 创建 3.9 分支，保留 3.8 的 GT top-K energy supervision、test-time temporal noise modulation、eval/PDM 逻辑。

3.12 将 temporal signal 限制为“分类排序正则”，不改主标签、不改主回归、不作用 top-K 外 mode。若 loss 曲线稳定且 PDM 或 3.11 rescoring 诊断改善，说明历史连接性适合被蒸馏为 mode ranking 偏好；若仍下降，则说明当前 temporal cost 与最终驾驶质量相关性不足，应优先继续改 cost 而不是加大训练 loss。

测试/验证结果：
本地不运行 pytest、manual runner 或 smoke。轻量测试文件已更新，覆盖 ranking 在 min_epoch 前不生效、rank loss 不生成 cls_soft_target、top-K 外 mode 不参与 ranking、energy detach 但 logits 可反传。等待服务器 smoke/full validation。

与论文撰写的关系：
3.12 可表述为 “Temporal Pairwise Ranking Distillation”。它把历史连接性从直接轨迹惩罚改为 GT top-K 内的弱排序监督，更接近 metric learning / ranking loss 思想，避免 3.9 中 soft target 和 auxiliary regression 对原始 DiffusionDrive 监督造成强干扰。

修改主题：3.1.01 GT-Protected Temporal Optimization
修改日期：2026-08-19

修改目的：
基于 3.14 ranking + tiny selected-mode temporal auxiliary，引入非对称多目标梯度保护。原始 DiffusionDrive 监督始终是主目标；历史连接监督只允许做细调，不能以一阶梯度方向损害主目标。该版本不替换 GT best mode、不改变 eval/PDM 选择逻辑，也不修改 temporal compatibility cost。

核心改动：
1. 将训练损失显式拆分为 primary_loss 与 temporal_connection_loss。primary_loss 保留原始 trajectory classification/regression、agent detection、BEV semantic 与 diffusion 目标；temporal_connection_loss 只包含 3.14 的 top-K pairwise ranking 和 tiny selected-mode temporal auxiliary。
2. GT best mode assignment、one-hot classification target 和原始 best-mode regression 均保持不变，连接性不再有机会替换主监督标签。
3. 只在 trajectory head 参数上分别计算 primary gradient 与 temporal gradient，感知骨干、检测分支和 BEV 分支不接收 temporal auxiliary 梯度。
4. 当两组梯度点积小于 0 时，只投影 temporal gradient 中与 primary gradient 冲突的分量；primary gradient 完全不修改。
5. 投影后的 temporal gradient 范数最多为 primary gradient 范数的 5%，即使两者方向一致，连接监督也只能作为细调信号。
6. 使用 surrogate loss 保持前向显示的总 loss 数值不变，同时让 Lightning 自动优化、AMP、DDP 和现有 optimizer/scheduler 继续使用原训练流程。
7. 新增诊断日志：gt_protection_active、gt_protection_conflict、gt_protection_cosine、gt_protection_primary_grad_norm、gt_protection_temporal_grad_norm、gt_protection_raw_ratio、gt_protection_applied_ratio、gt_protection_scale。
8. 修正 3.14 中 _energy_supervision() 未显式接收 poses_cls 的接口缺陷，确保 ranking loss 启动后能对分类 logits 反向传播。

预期影响：
3.1.01 将“GT 是粗准焦、历史连接是细准焦”落实为梯度级约束，而不是继续依赖更小的标量 loss 权重。连接目标与原始目标一致时允许小幅更新；发生冲突时删除有害分量；无论是否冲突都限制为主梯度的 5%。这不能保证 PDM 一定提升，但能显著降低 3.5-3.9 中 auxiliary loss 带偏主训练方向和引发不稳定的风险。

测试/验证结果：
按实验约定，本地不运行 pytest、manual runner 或 smoke。轻量测试已补充冲突投影、同向梯度限幅，以及 3.14 ranking logits 接口覆盖；等待服务器 smoke/full validation。

与论文撰写的关系：
该版本可表述为 “GT-Protected Temporal Fine Adjustment”。方法属于面向主目标优先级的非对称梯度协调：历史连接不是与 imitation objective 平权竞争的第二目标，而是在不牺牲原始监督一阶下降方向的约束下，对 trajectory head 进行有限幅度的时序细化。

核心改动：
1. 新增 navtrain GT 提取脚本，复用 navtrain scene filter 的 log/token/route/滑窗语义，从 trainval 原始日志直接生成与模型一致的 `[N,8,2]` ego-local XY trajectory，不依赖相机、LiDAR 或 map API。
2. 新增纯 NumPy anchor metrics：pairwise ADE、max point distance、ADE assignment、严格 epsilon coverage、cluster variance、cluster statistics 和论文对比指标；assignment/coverage 支持分批计算，避免 navtrain 全量矩阵长期驻留内存。
3. 新增 Coverage-guided Base Expansion：以官方 20 anchors 为 root，结合 P95 max error、cluster variance、sample support、uncovered count 选择 split cluster，使用 local K-Means(K=2) 替换父节点，每轮执行全局 re-assignment；支持 coverage target、收益饱和、无候选和 max-base safety cap 停止条件。
4. Base tree 使用稳定 node_id/parent_id 记录 split 血缘，所有 child 永久继承原始 root_id，便于后续 same-root residual learning 和论文可视化。
5. 新增 root-conditioned tangent-normal residual codebook：GT residual 按 nearest Base 和原始 root 聚合，第一版使用轻量 base-local frame，不实现完整道路 Frenet 投影；每个 root 显式保留 zero residual，并输出 M=1/2/4/8/16 distortion curve。
6. 新增 data-support composition：只生成同 root 且满足 min support/min ratio 的 Base-Residual pair；zero residual 始终保留；最终按 trajectory ADE 去重，并优先保留 support 更高和原始 Base 候选。
7. 同时导出 Final NPY、Base-only NPY、完整 NPZ metadata、JSON report 和 Base Expansion 曲线图。JSON 对比初始 20、Expanded Base、Base+Residual 的 Coverage@0.5/1.0/1.5/2.0m、mean/P95 nearest ADE 和 P95 max error。
8. DiffusionDrive 删除 decoder 中无效的固定 20-mode constructor 参数；TrajectoryHead 校验 anchor shape/finite 值，并从 `plan_anchor.shape[0]` 自动推导 K；相关 shape 注释更新为 K。
9. checkpoint 加载时不再恢复 state_dict 内的 plan_anchor。当前配置选择的离线 anchor 文件始终为权威来源，既避免旧 20-anchor checkpoint 覆盖新 bank，也避免 variable-K checkpoint shape mismatch。
10. 保持 temporal compatibility、top-K ranking、tiny auxiliary、GT-protected gradient projection 和 test-time rescoring 算法不变；原有动态 top-K 保护继续适配可变 K。
11. 新增轻量测试，覆盖距离/assignment/coverage、双峰 split、紧密单峰不 split、连续 split root inheritance、tangent-normal round trip、zero residual 保留 Base，以及 K=20/32/64 的 anchor 加载、refinement shape、stubbed forward_train/forward_test。

预期影响：
Anchor Bank 的表示容量由 navtrain 数据覆盖需求驱动，不再受固定 20 模态限制；Base Expansion 用于改善 coarse trajectory coverage，root-conditioned residual 用于在不跨意图错误组合的前提下补充局部行为模式。模型计算量仍随最终 K 近似线性增长，因此默认 max_base_anchors=64 仅作为首轮工程 safety cap，最终 K 应根据 coverage 收益、显存和速度共同确定。
