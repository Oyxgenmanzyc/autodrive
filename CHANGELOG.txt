修改主题：3.1.02 原版 DiffusionDrive + Adaptive Multimodal Anchor
修改日期：2026-08-22

修改目的：
在原版 DiffusionDrive 上单独验证自适应多模态 anchor，不引入 3.1.01 的 temporal-pair 训练、GT-protected 梯度投影、temporal energy/ranking loss 或跨帧推理状态，保证 anchor 消融实验变量独立。

涉及文件：
navsim/agents/diffusiondrive/anchors/
navsim/agents/diffusiondrive/modules/multimodal_loss.py
navsim/agents/diffusiondrive/transfuser_agent.py
navsim/agents/diffusiondrive/transfuser_model_v2.py
scripts/anchors/
docs/adaptive_anchor_bank.md
tests/test_adaptive_anchor_bank.py
tests/test_diffusiondrive_variable_anchor.py

核心改动：
1. 从 navtrain GT 提取 `[N, 8, 2]` ego-local 轨迹，离线构建 adaptive anchor bank。
2. 通过 base split、root-conditioned tangent-normal residual codebook、support mask 和 ADE 去重生成多模态 anchor。
3. TrajectoryHead 从 anchor 文件 shape 自动推导候选数量 K，不再固定为 20。
4. decoder、分类分支、回归分支、训练 loss 和推理 gather 均沿用原版 DiffusionDrive，并支持动态 K。
5. 加载旧 checkpoint 时过滤其中的 `plan_anchor`，避免 20-anchor checkpoint 覆盖当前 adaptive bank；其余模型参数保持兼容加载。
6. 对 anchor 文件执行 shape、非空和有限值校验。
7. 未包含 temporal-pair dataset、TemporalPairAgentLightningModule、上一帧轨迹缓存、temporal noise、temporal rescoring、energy ranking 或 GT-protected gradient。

预期影响：
仅改变 DiffusionDrive 的离散轨迹候选集合及候选数量，使长尾轨迹和局部运动模式获得更好的 anchor 覆盖。计算量和显存预计近似随 K 线性增加。

测试/验证结果：
本地不运行训练或完整 smoke test；待服务器执行 anchor 单元测试、variable-K 单元测试和 4 卡 fast-dev-run。

与论文撰写的关系：
该版本作为“原版 DiffusionDrive + Adaptive Multimodal Anchor”的独立消融实验，与 3.1.01 时序优化实验分离，可用于直接比较固定 20-anchor 与 adaptive variable-K anchor 的覆盖率、训练稳定性及 NAVSIM 指标。
修改主题：0_89.6pdm 定稿——K67 + PCS + Cost Ranker
修改日期：2026-09-21

修改目的：
从 3.1.02 K67 基线重建干净定稿，只保留已在完整 navtest 获得最佳结果的候选生成、PCS评分和代价敏感排序链路。

核心改动：
- 冻结 K67 自适应多模态 Anchor 生成器，保留67条候选与原两步DDIM推理。
- PCS独立预测每条候选的五项PDM分量与合成分数，不更新生成器。
- Cost Ranker读取冻结PCS特征、分项、分数、原分类概率和轨迹几何，通过候选Self-Attention预测有界排序残差。
- 最终选择分数为 PCS score + 0.25 * residual；残差头零初始化，初始行为严格回退原PCS。
- 只训练代价加权pairwise ranking loss；按日志三折OOF教师仅用于难例挖掘。
- navtrain val按日志拆分calibration/audit；audit不参与epoch或alpha选择。
- navtest评估只输出rank、PCS和base，不再加载TRV checkpoint。

去除的冗余实验：
- TRV三风险否决器、GTRS保守选择器。
- Generator Brake Timing与Timing Cross-Attention Generator。
- Post-selection Timing Refiner与Gated Paired Timing Refiner。
- predicted-margin gate、future-occupancy veto及其缓存/训练依赖。

正式结果：
- 12,146场景完整navtest：rank 0.8945933668，PCS 0.8907557098，base 0.8848893597。
- 相对PCS提升0.383766 PDM点；NC、DAC、TTC、comfort、direction均值提高，ego progress轻微下降。
- 分支名0_89.6pdm为用户指定实验名；论文与报告使用未经取整的真实分数0.8945933668。

验证状态：
- 复用已完成的服务器完整训练与navtest结果。
- 干净分支未重新执行服务器eval；用户明确要求直接定稿上传。代码裁剪没有改动K67、PCS或Cost Ranker权重与排名计算，只移除了TRV对照的加载和输出。

修改主题：3.1.05_11 生成器内的纵向时机 mode（独立实验）
修改日期：2026-10-09

修改目的：针对第一瓶颈——原 K67 只显式覆盖空间路径，早/晚驾驶时机并非受控生成自由度。3.1.05_10 的生成后固定变形与选择器在独立 audit 失效，不能将其当作此瓶颈的验证。

涉及文件：navsim/agents/diffusiondrive/generator_timing/、navsim/planning/script/run_generator_timing.py、navsim/planning/script/generator_timing_eval.py、scripts/pcs/run_3_1_05_11.sh、tests/test_generator_timing.py、docs/experiment_3_1_05_11_generator_timing.md、training_and_eval_3_1_05_11.txt。

核心改动：每个 K67 空间 anchor 建立早/晚时机种子；134 条新增候选在原冻结 DDIM 两步、每层解码中由时机条件和可训练残差生成。数据侧对每个原候选独立构造并官方打分早/晚目标；仅安全且时机不同的目标监督对应 mode，不把同一 GT 轨迹强压给所有 mode。仅训练新增时机模块，原 67 条候选、PCS 和 Cost Ranker 权重保持冻结。校准/audit 与 201 候选固定后处理、多采样等量对照，只有通过独立 audit 才允许 navtest。

预期影响：将时机差异从生成后的轨迹编辑前移到候选生成；能否提升仍须以生成候选的官方 Oracle、独立 audit 与等量对照判断，不能由教师 Oracle 推断成功。

测试/验证：本地未运行训练或 smoke；须在服务器依次执行 check、test、pilot、完整标签缓存、smoke-train、20 epoch 正式训练和独立 validate。当前不声称 PDM 提升。

与论文关系：提供“显式空间×时机 mode 是否有效”的直接消融，区分候选数量收益、固定后处理收益与真正生成器时机条件收益。

兼容性修正（2026-10-09）：恢复 transfuser_config.py 中原 K67 候选缓存记录的只读 anchor_diagnostics 配置字段，使八项源码 SHA256 与旧缓存严格一致。该字段不参与训练或推理；禁止跳过候选缓存的 provenance 校验。

验证精度修正（2026-10-10）：缓存 BEV/agents/ego 以 FP16 保存，PCS 与 timing 训练分支原先已有转回 FP32 的边界；额外 DDIM 采样对照直接接收缓存，遗漏转换而在 Conv2d 报 Half/float 不匹配。统一验证输入在 _candidate_context 转为 FP32，保留缓存原有数值精度；新增半精度缓存进入单精度卷积的回归测试。该修正仅涉及验证代码，不改训练模块、教师缓存或已完成的 20 轮 checkpoint。本地未运行测试；待服务器单元测试和验证 Pilot。
