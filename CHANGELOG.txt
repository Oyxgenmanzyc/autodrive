修改主题：3.1.05 Scene-conditioned Proposal Reconstruction（SPR，场景条件候选重构）
修改日期：2026-09-05

修改目的：
在 3.1.02 diagnostics 基线上迁移 MeanFuser 候选重构模块，结合全部 refinement
proposals 与场景 query 生成最终轨迹，检验能否改善硬分类选择导致的误差及 PDM。

基线与来源：
基线 change/20260905-adaptive-anchor-diagnostics-3.1.02，
ddaafbc35785b5f4e2d2b03d5b56393b6c3e6096。
新分支 change/20260905-scene-proposal-reconstruction-3.1.05。
上游 https://github.com/wjl2244/MeanFuser，
8de8ba6244834645192e318dcc437d124cfd6872。

涉及文件：
navsim/agents/diffusiondrive/modules/scene_proposal_reconstruction.py
navsim/agents/diffusiondrive/modules/proposal_trajectory_utils.py
navsim/agents/diffusiondrive/transfuser_model_v2.py、transfuser_config.py
navsim/agents/diffusiondrive/transfuser_agent.py、transfuser_loss.py
navsim/planning/script/config/common/agent/diffusiondrive_spr_agent.yaml
scripts/training/run_diffusiondrive_spr_training.sh
scripts/evaluation/run_diffusiondrive_spr.sh
tests/test_scene_proposal_reconstruction.py、test_diffusiondrive_variable_anchor.py
third_party/meanfuser/LICENSE、NOTICE.md
docs/experiment_3_1_05_spr.md

核心改动：
1. 复用上游三层 TransformerDecoder、MLP、初始化及 normalized delta/sin/cos L1，
   保留 embedded_vocab + norm(cross_attn_output) 顺序和原始归一化统计。
2. K 来自现有 bank；将 [B,K,8,3] 转换为上游表示，memory 为 ego + agent query；
   坐标转换、累计与损失使用 FP32。
3. 保留 DDIM、anchor 构建、候选分类及 best-mode 回归；训练复用最后一层候选，
   推理复用最后一次采样候选，每次只重构一次，不增加 DDIM rollout。
4. 默认 detach 候选坐标，保留上游无梯度采样边界；仍更新共享场景编码器。
5. spr_loss_weight=2.0 在 trajectory_loss 内部，外层默认乘 12，
   因此新增损失实际总权重为 24，只计入一次；该设置未经调参验证。
6. 基础 agent 默认关闭 SPR；新 diffusiondrive_spr_agent 启用，
   spr_output=selector 支持同一 checkpoint 输出消融。
7. 添加 detached 的 spr_ade、selector_ade、proposal_oracle_ade；
   原 anchor diagnostics callback 不变。
8. 旧 checkpoint 可训练热启动，但 SPR 评测要求完整新头参数。
   已含 SPR 的 checkpoint 要求 bank 数值和顺序与训练一致。

预期影响：
可能改善最终轨迹误差，但 ADE 降低不保证 PDM 上升；训练与推理候选分布差异
仍存在。当前没有 PDM 增益结论，也不以 MeanFuser 整体分数替代本实验结果。

测试/验证结果：
完成源码与接线审阅，添加纯 Torch、轻量集成和 CUDA AMP 测试。
遵循 autodrive-experiment-workflow，本地未运行 pytest、smoke、语法检查或 PDM；
not run locally; pending server smoke test。
服务器运行及基线/同权重 selector 消融方法见 docs/experiment_3_1_05_spr.md。

与论文撰写的关系：
SPR 是本地功能命名，核心迁移自 MeanFuser ARM，许可证及来源随代码保留。
须引用原工作、说明适配边界，不能把改名当作原创；贡献需由真实 PDM 消融支撑。

修改主题：新 3.1.02：保留原算法，迁回 3.1.02_2 的只读诊断能力
修改日期：2026-09-05

修改目的：
以 0c18ceb（原版 DiffusionDrive + Adaptive Multimodal Anchor）为基底，按用户要求结束当前 3.1.02_2 消融排查，仅迁回不会参与预测、匹配或反向传播的统计与离线分析功能。

涉及文件：
navsim/agents/diffusiondrive/anchor_diagnostics_callback.py
navsim/agents/diffusiondrive/anchors/diagnostics.py
navsim/agents/diffusiondrive/transfuser_config.py
navsim/agents/diffusiondrive/transfuser_agent.py
scripts/anchors/diagnose_anchor_bank.py
scripts/anchors/merge_anchor_diagnostics.py
tests/test_anchor_diagnostics.py
tests/test_anchor_diagnostics_callback.py
docs/anchor_diagnostics_3_1_02.md

核心改动：
1. 从 3.1.02_2 的 utilization/diversity 诊断思想中提取只读能力，适配原版全局 ADE 静态匹配、普通 NPY bank；不直接合并其模型或损失实现。
2. 可选 anchor_diagnostics=false（默认）：启用后用 detached forward hook 记录每个 decoder 层的静态 winner / logit top1 计数、频率、活跃率、熵、分类/回归损失、非有限 batch 数和实际 optimizer group LR。
3. 统计不注册模型参数或 buffer、不写入 checkpoint、不额外调用模型 forward、不抽随机数；每个 rank 独立写 JSON，训练中不引入 collective。全局统计在训练外先求和计数再计算熵。
4. 增加原版 NPY anchor 的离线支持度、最近邻 ADE、近重复比例、覆盖率报告及总览/逐条/支持度可视化；只读原 bank，不更改生成或去重结果。
5. 原版 base + residual 构建、静态 ADE winner、focal mean + L1、全部 loss weights、DDIM 推理、optimizer/scheduler、训练缓存构造均保留。没有迁入 command mask、D_traj、动态 WTA、K-invariant focal 或 1.5% child ratio。

预期影响：
默认关闭训练诊断时保持原训练/推理数值路径；启用时仅增加观测和 I/O 开销。此版本不宣称获得新的 PDM 分数，既有约 88.44 的成绩属于原 checkpoint 与原评测配置。

测试/验证结果：
按实验工作流未在本地运行测试、语法检查或训练；待服务器执行新增单元测试和 4 卡跨两轮 smoke test。新增测试覆盖 loss/gradient/RNG/checkpoint 状态不变、分层计数、不统计验证、NaN 只记录不修复、禁止 collective、离线合并完整性、覆盖与重复度边界。

与论文撰写的关系：
本版为原 3.1.02 的观测增强版，不作为额外算法增益。3.1.02_2 的消融结果保留为独立实验，不将诊断模块归因为 PDM 改善。

修改主题：3.1.02 原版 DiffusionDrive + Adaptive Multimodal Anchor
修改日期：2026-08-22

修改目的：
在原版 DiffusionDrive 上单独验证自适应多模态 anchor，不引入 3.1.01 的 temporal-pair 训练、GT-protected 梯度投影、temporal energy/ranking loss 或跨帧推理状态，保证 anchor 消融实验变量独立。

涉及文件：
navsim/agents/diffusiondrive/anchors/
navsim/agents/diffusiondrive/modules/multimodal_loss.py
navsim/agents/diffusiondrive/transfuser_agent.py
navsim/agents/diffusiondrive/transfuser_model_v2.py
scripts/anchors/
docs/adaptive_anchor_bank.md
tests/test_adaptive_anchor_bank.py
tests/test_diffusiondrive_variable_anchor.py

核心改动：
1. 从 navtrain GT 提取 `[N, 8, 2]` ego-local 轨迹，离线构建 adaptive anchor bank。
2. 通过 base split、root-conditioned tangent-normal residual codebook、support mask 和 ADE 去重生成多模态 anchor。
3. TrajectoryHead 从 anchor 文件 shape 自动推导候选数量 K，不再固定为 20。
4. decoder、分类分支、回归分支、训练 loss 和推理 gather 均沿用原版 DiffusionDrive，并支持动态 K。
5. 加载旧 checkpoint 时过滤其中的 `plan_anchor`，避免 20-anchor checkpoint 覆盖当前 adaptive bank；其余模型参数保持兼容加载。
6. 对 anchor 文件执行 shape、非空和有限值校验。
7. 未包含 temporal-pair dataset、TemporalPairAgentLightningModule、上一帧轨迹缓存、temporal noise、temporal rescoring、energy ranking 或 GT-protected gradient。

预期影响：
仅改变 DiffusionDrive 的离散轨迹候选集合及候选数量，使长尾轨迹和局部运动模式获得更好的 anchor 覆盖。计算量和显存预计近似随 K 线性增加。

测试/验证结果：
本地不运行训练或完整 smoke test；待服务器执行 anchor 单元测试、variable-K 单元测试和 4 卡 fast-dev-run。

与论文撰写的关系：
该版本作为“原版 DiffusionDrive + Adaptive Multimodal Anchor”的独立消融实验，与 3.1.01 时序优化实验分离，可用于直接比较固定 20-anchor 与 adaptive variable-K anchor 的覆盖率、训练稳定性及 NAVSIM 指标。
